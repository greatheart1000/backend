# 相似查询处理流程

## 场景描述

当用户输入一个新问题，系统如何处理与历史查询相似的情况？以下是一个详细的处理流程说明。

## 处理流程示例

### 场景设定
1. **第一次查询**："什么是人工智能？"
2. **一段时间后相似查询**："人工智能是什么？"

### 详细数据流过程

#### 第一次查询处理流程

```
用户输入: "什么是人工智能？"
    ↓
[阶段1: 意图识别]
- 检查缓存A: 未命中
- 调用意图分类模型: 识别为"A类：事实问答"
- 计算权重: BM25权重0.7, Vector权重0.3
- 存入缓存A: key="intent:hash(什么是人工智能？)", value=("A类：事实问答", {BM25:0.7, Vector:0.3})

    ↓
[阶段2: 向量化与会话管理]
- 检查缓存D: 未命中
- 调用嵌入模型: 生成查询向量
- 存入缓存D: key="query_vector:hash(什么是人工智能？)", value=[0.1, 0.2, 0.3, ...]
- 获取会话历史: 缓存E中无历史记录

    ↓
[阶段3: 混合检索]
- 检查缓存B: 未命中
- 调用Elasticsearch: 执行BM25+向量混合检索
- 获取Top 100候选文档
- 存入缓存B: key="hybrid_search:hash(什么是人工智能？):0.7:0.3", value=[doc1, doc2, ...]

    ↓
[阶段4: 精排与融合]
- 检查缓存C: 未命中
- 调用BGE Reranker: 对候选文档进行精排
- 获取Top 10文档

    ↓
[阶段5: 答案生成]
- 调用Qwen API: 基于Top 10文档生成答案
- 生成答案: "人工智能是计算机科学的一个分支..."

    ↓
[阶段6: 结果返回与缓存]
- 存入缓存C: key="final_answer:hash(什么是人工智能？):default", value="人工智能是计算机科学的一个分支..."
- 更新会话历史: 存入缓存E
- 返回答案给用户
```

#### 相似查询处理流程（语义相似度缓存）

```
用户输入: "人工智能是什么？"
    ↓
[阶段1: 意图识别]
- 检查缓存A: 未命中（因为是不同查询）
- 调用意图分类模型: 识别为"A类：事实问答"
- 计算权重: BM25权重0.7, Vector权重0.3
- 存入缓存A: key="intent:hash(人工智能是什么？)", value=("A类：事实问答", {BM25:0.7, Vector:0.3})

    ↓
[阶段2: 向量化与会话管理]
- 检查缓存D: 未命中
- 调用嵌入模型: 生成查询向量
- 存入缓存D: key="query_vector:hash(人工智能是什么？)", value=[0.15, 0.22, 0.28, ...]
- 获取会话历史: 从缓存E获取历史

    ↓
[阶段3: 精确缓存匹配]
- 检查缓存C: 未命中（因为是不同查询）

    ↓
[阶段4: 语义相似度缓存匹配]
- 执行语义相似度搜索
- 计算当前查询向量与缓存查询向量的余弦相似度
- 发现与"什么是人工智能？"的相似度为0.96（>0.95阈值）
- 直接返回缓存的答案: "人工智能是计算机科学的一个分支..."
- 标记为语义相似度缓存命中

    ↓
[结果返回]
- 直接返回缓存答案
- 更新会话历史
- 响应时间：毫秒级
```

## 高级优化策略

### 1. 语义相似度缓存

系统通过计算查询间的语义相似度来实现更智能的缓存复用：

```python
def semantic_cache_lookup(query_vector, threshold=0.95):
    """
    基于语义相似度的缓存查找
    """
    # 获取所有缓存的查询向量
    cached_vectors = get_all_cached_vectors()
    
    # 计算相似度
    for cached_vector in cached_vectors:
        similarity = cosine_similarity(query_vector, cached_vector)
        
        # 如果语义相似度超过阈值，复用缓存答案
        if similarity > threshold:
            return get_cached_answer(cached_vector.hash)
    
    return None  # 未找到相似缓存
```

### 2. 相似度阈值配置

系统支持配置相似度阈值，平衡准确性和缓存命中率：
- **高阈值**(0.95+)：高准确性，较低命中率
- **中阈值**(0.90-0.95)：平衡准确性和命中率
- **低阈值**(<0.90)：高命中率，可能降低准确性

### 3. 模糊匹配优化

对于高度相似的查询，系统可以采用模糊匹配策略：

1. **编辑距离计算**：计算新查询与缓存查询的编辑距离
2. **关键词重叠度**：计算关键词的重叠程度
3. **语义相似度**：使用向量计算语义相似度

## 性能对比

| 查询类型 | 处理阶段 | 平均响应时间 | 缓存类型 |
|---------|---------|-------------|---------|
| 首次查询 | 完整RAG流程 | 2-5秒 | 无缓存 |
| 相同查询 | 缓存命中 | 50-200毫秒 | 精确匹配 |
| 相似查询 | 语义缓存命中 | 100-300毫秒 | 语义相似度 |
| 相似查询 | 部分缓存复用 | 1-3秒 | 部分复用 |

## 实际应用建议

1. **缓存键设计**：使用内容哈希而非简单字符串匹配，提高缓存命中率
2. **缓存过期策略**：根据业务需求设置合理的缓存过期时间
3. **相似度阈值**：根据业务场景调整语义相似度阈值（建议0.90-0.95）
4. **监控指标**：监控各缓存层的命中率，持续优化缓存策略
5. **Redis Cluster**：在高并发场景下使用Redis Cluster提升性能

通过这种多级缓存设计和语义相似度匹配，系统能够在保证答案质量的同时，显著提升用户查询体验，特别是对于语义相同但表达不同的查询。
